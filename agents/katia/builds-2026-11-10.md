## Shipped

**The fix went into the guard that already owned the ladder, not into a new checker.**

The brief asked for a price-ladder checker. There already is one: `price-ladder` →
`ops/price-ladder-guard.py`, registered since 28 Oct. **Two verdict owners for one rule is how a
defect survives** — one file says the ladder is fine, the other says it is broken, and the reader
cannot tell which one runs. So the ladder rule stays in the guard, the guard was repaired, and the
registry did **not** gain a row.

**`ops/price-ladder-guard.py`** — repaired, in place:

1. **The P1 crash is fixed.** `main()` read `rep.unproven` at the exit contract, but no code ever
   set it — so the guard raised `AttributeError: 'Report' object has no attribute 'unproven'` and
   exited non-zero **every single time**, including when the ladder was fine. `Report` now carries
   `unproven: bool = False`, and it is set when the live storefront feed or the catalogue cannot be
   read. **An unreadable scope returns rc 2 / `COULD NOT PROVE` — never `CLEAN`.** A guard that
   crashes on every run is not a red guard; it is no guard, and it was reporting on nothing.
2. **The empty-price crash is fixed.** `int(p["price"])` raised `ValueError: invalid literal for
   int() with base 10: ''` on a variant with a blank price.
3. **The baseline is now same-family.** The case must be compared against **N of the singles it
   actually replaces** — the Gold 7kg case against seven **Gold 1kg** units, not against the
   Luxury line. Pairing across families produced a nonsense verdict.
4. **The live bulk-vs-singles rule is in.** A larger pack that costs **more per kg** than N of the
   smaller pack it replaces is a **premium dressed as a case** — a finding, not a rounding.

**`ops/test-price-ladder.py`** — the regression suite for the rule.

The case that matters most is in it: **a synthetic ladder where the case is dearer per kg than N
singles MUST produce a non-clean verdict.** A checker whose verdict function can only return clean
is a checker that passes vacuously, and we have been burned by that shape before. The suite also
proves the inverse — a correctly-ordered ladder returns clean — so the rule is tested in **both**
directions rather than being always-green.

**`studex-meat/PRICE-SOURCE-REGISTRY.md` §5 item 2 — REOPENED and corrected.** The 21 Oct closure
said the 7kg case is "a **~19% volume discount** … **No change needed.**" Two errors: a case that
costs **more** per kg is a **premium**, not a discount — the real number is **+23.2%** — and "19%"
matches neither that nor anything else (R12,500 ÷ 7 = **R1,785.71/kg** against R1,450/kg). The note
also claimed "our pages already match the store exactly", which is false: our pages advertise the
owned ladder. **The 7kg closure note is now the finding, not the reassurance.**

**What was deliberately NOT done:** no new registry row, and **no `HEARTBEAT.md` section from this

## The one thing this build does NOT fix

**The store still charges R450 / R1,450 / R12,500 against owned R325 / R1,250 / R8,400.** The
`SHOPIFY_API_TOKEN` in `.env` answers **HTTP 401** on the Admin API, so no write is possible from
here. `ops/fix-shopify-price-drift.py` computes the exact edits and is **dry-run by default**.

The repaired guard **detects and quantifies** the ladder problem; it does not fix it. Fixing it needs
`SHOPIFY_ADMIN_TOKEN` with `write_products` from the owner.

## Owner decision this build surfaces

The registry and the store now disagree, and the checker makes the disagreement impossible to
ignore:

| | owned | live | per-kg (owned) | per-kg (live) |
|---|---|---|---|---|
| 500g | R325 | R450 | — | — |
| 1kg | R1,250 | R1,450 | R1,250 | R1,450 |
| 7kg case | R8,400 | R12,500 | **R1,200** | **R1,786** |

- **Fix the store to the owned prices** → the case becomes a genuine **4.0% discount** and every
  customer gets the advertised price. *This is what the registry says is correct.*
- **Or bless the drift** → the case is a **23.2% per-kg premium** and should be repriced to about
  **R10,150** to match seven bags, and the "beats seven 1kg bags" claim on the page must come down.

We are currently shipping the worst of both: the premium price *and* the "no change needed" note.

  be the reason a price looks fixed.

  tariff line. A file cannot unblock it and a tracker would only make the stall look like progress.
- **Backfilling 09 Nov's brief** — that night's lane died on the same rate limit, and inventing a
  brief for it would be the exact failure mode this build exists to prevent. **09 Nov's research
  and build files stay missing, and stay honestly missing.**
