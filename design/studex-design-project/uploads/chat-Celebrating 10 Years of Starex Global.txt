## Phone Recommendation

For an iPhone running Linux through UTM, I would use:

```text
UTM SE
  → Alpine Linux ARM64
    → PicoClaw ARM64 binary
      → remote model API
```

PicoClaw is the safest practical choice because it is a single Go binary, supports ARM64, RISC-V, MIPS and x86, starts rapidly, and currently uses roughly 10–20 MB RAM. It also has official Android support. However, the developers still warn that it is pre-1.0 and should not yet be treated as production-grade. [PicoClaw repository](https://github.com/sipeed/picoclaw)

Important limitations:

- UTM SE on an ordinary non-jailbroken iPhone has no JIT and is substantially slower than native execution. Its documentation specifically recommends stripped-down systems such as Alpine Linux. [UTM iOS documentation](https://docs.getutm.app/installation/ios/)
- Use an ARM64 Alpine image on an ARM iPhone; do not emulate x86 Linux unless absolutely necessary.
- Do not attempt to run a large local LLM inside UTM SE. Let PicoClaw call OpenAI, Anthropic, Gemini, DeepSeek, Kimi, MiniMax, GLM, Qwen or another remote endpoint.
- On Android, skip UTM entirely: use the official PicoClaw APK or a native ARM64/Termux installation. That will be faster, consume less battery and produce fewer compatibility errors.

## Comparison

| Project | Best use | Resource profile | My assessment |
|---|---|---:|---|
| [OpenClaw](https://github.com/openclaw/openclaw) | Full personal/business assistant | Node.js, relatively heavy | Best ecosystem, channels, plugins and support; not ideal inside phone UTM |
| [PicoClaw](https://github.com/sipeed/picoclaw) | Phones, routers, SBCs and cameras | Approximately 10–20 MB RAM | Best practical lightweight choice |
| [ZeroClaw](https://github.com/zeroclaw-labs/zeroclaw) | Security, hardware control and automation | Single Rust binary | Strong second choice; more security controls and hardware abstractions than PicoClaw |
| [NullClaw](https://github.com/nullclaw/nullclaw) | Extremely constrained Linux devices | Claims 678 KB binary and ~1 MB RAM | Smallest, but its benchmark is self-published and its ecosystem is less proven |
| [MicroClaw](https://github.com/microclaw/microclaw) | Durable jobs and recoverable automation | Rust plus SQLite | Interesting reliability design: checkpoints, durable delivery and a designated stable branch |
| [NanoClaw](https://github.com/nanocoai/nanoclaw) | Container-isolated personal agents | Node, Docker and per-agent containers | Easier to audit than OpenClaw, but unsuitable for UTM SE and most phones |
| [NemoClaw](https://github.com/NVIDIA/NemoClaw) | Controlled enterprise/RTX/DGX deployment | Containers, OpenShell and sandbox infrastructure | A security/deployment layer around agents, not a tiny replacement runtime |
| [IronClaw](https://github.com/nearai/ironclaw) | Security-sensitive business systems | Rust, WASM, optional Docker/Postgres | Promising but heavier and operationally more complex |
| [MimiClaw](https://github.com/memovai/mimiclaw) | ESP32 sensors and tiny assistants | 8 MB PSRAM, 16 MB flash | Best microcontroller design, but its LLM reasoning happens through a cloud API |

I would not choose NullClaw solely because its README reports the smallest number. The published measurements are produced by the project itself and are not an independent, controlled benchmark. Its footprint is impressive, but “smallest” does not automatically mean “fewest errors.”

Likewise, none of these smaller projects has yet demonstrated the same breadth of real-world integrations as OpenClaw. PicoClaw is the best compromise between footprint, activity, platform support and community adoption.

## Cameras And Edge Devices

The most credible ready-to-build camera route is Sipeed:

```text
MaixCAM / MaixCAM2
  ├── local camera and YOLO detection
  ├── PicoClaw agent runtime
  ├── MaixPy-generated device scripts
  └── local or remote multimodal model
```

Sipeed officially documents PicoClaw controlling MaixCAM/MaixCAM2, opening the camera, creating MaixPy scripts, running YOLO and reading detection results. [Official MaixCAM–PicoClaw guide](https://wiki.sipeed.com/maixpy/doc/en/basic/picoclaw.html)

For a product such as a security camera, retail camera, factory inspection camera or smart doorbell, I would split the system:

- Run motion detection, person/object detection and simple rules locally.
- Send only selected frames to MiniCPM-V or another vision model.
- Let PicoClaw handle workflow, notifications, scheduled checks and business integrations.
- Keep destructive actions behind explicit approval rules.

For a stronger phone or embedded Linux board, [MiniCPM-V 4.6](https://github.com/OpenBMB/MiniCPM-V) is especially relevant. It is a 1.3B vision-language model with official iOS, Android and HarmonyOS deployment guidance. It can understand images and video and is much more appropriate for a camera product than a text-only LLM.

For text-only local reasoning, MiniCPM5-1B has a roughly 657 MB Q4 GGUF build intended for edge/mobile-class hardware. It is still far larger than the Claw runtime itself—the agent framework might consume 10 MB while the model consumes hundreds of megabytes or several gigabytes. [MiniCPM llama.cpp deployment](https://github.com/OpenBMB/MiniCPM/blob/main/docs/deployment/llama_cpp.md)

MimiClaw is appropriate when the device is only an ESP32-S3. It runs the agent loop, Telegram connection, memory and scheduling in C, but sends reasoning requests to Anthropic or OpenAI. An ESP32 cannot locally run MiniCPM-V; it acts as the sensor/controller front end.

## Chinese Ecosystem

The strongest candidates for building this type of device are:

- Sipeed: the clearest integrated hardware/software route through PicoClaw, MaixCAM and LicheeRV boards.
- OpenBMB/ModelBest: MiniCPM language and vision models designed for phone and edge deployment.
- Alibaba Qwen: strong multilingual vision and tool-use models, generally better suited to server, cloud or powerful edge hardware than UTM on a phone.

- Canaan, Rockchip-based manufacturers, Luckfox, Firefly, M5Stack and Seeed Studio: plausible hardware partners, but Sipeed currently has the most directly documented Claw-to-camera integration.
